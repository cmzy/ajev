# AJev：自训练 Jev 类决策模型 — 技术调研与方案

> 调研日期：2026-09-30　｜　训练平台：Google Colab

---

## 1. Jev 到底是什么

**Jev 是 TypeSafe 的“System One”决策模型**：不生成文本，只回答“带类型的问题”，一次前向就输出**校准过的概率分布**。

```
输入: state(文本/JSON) + questions{ id: {type, instructions, criteria} }
输出: answers{ id: 概率分布 + 选中项 + confidence }
```

| 题型 | 含义 | 输出 |
|---|---|---|
| `noul` | 是/否（语义 if） | `P(yes)` ∈ [0,1] |
| `choice` | 多选一（≤255 个选项） | 选中项、各选项概率、confidence |
| `score` | 有序等级（2–10 级） | 概率加权的分数、各级概率、confidence |

- `confidence = 1 − H(p) / ln K`：完全确定时为 1，均匀分布时为 0。
- 多个问题共享同一个 state，可以并行回答（fan-out）。
- 输出只能落在 schema 内，所以“类型错误率 = 0%”。
- 训练方法是 **RLCD（Reinforcement Learning for Calibrated Decisions）**：用 strictly proper scoring rule（log / Brier / spherical / RPS）作为奖励，逼着模型“说真话”，让概率和实际命中率对得上。
- 局限：不会写作，不会做数学和计数，对措辞很敏感。

**所以我们要训练的东西 =「把 state + 问题 + 选项」映射成「选项上的校准概率分布」的模型。** 这本质上是带校准目标的**通用零样本分类器**，不是聊天模型。

## 2. 现有开源复刻对比

| 项目 | 架构 / 基座 | 参数 | 训练 | 硬件 | 关键结果 |
|---|---|---|---|---|---|
| **OpenJev** (razorback16) | DiffusionGemma 26B-A4B（离散扩散，把答案槽 mask 掉，一次去噪就读出分布） | 26B / 4B 激活 | 微调降低选项顺序敏感（18.5% → 2.3%） | ≥24GB 推理 | 34 个公开数据源共 10k 题，准确率 84.0% |
| **Laya** (convaiinnovations) | ModernBERT-large + 决策头（2 层 Transformer + option-marker 打分器 + act/escalate） | 421M | RLCD（GRPO 式 REINFORCE，以组均值作 baseline） | **Kaggle 2×T4，4–5 小时**（约 3 万题，4 epoch） | typed-decisions 0.766（Jev 0.727） |
| Laya-multilingual | mmBERT-base | 322M | 同上 | 同上 | 100+ 语言，MASSIVE 上 48/51 种语言超过 3 倍随机水平 |
| **Verdict 2.0** (Heman10x) | ModernBERT-base + GLiClass 头 | 151M | 软标签 + 对称的 Permutation-KL（打乱选项顺序）+ 独立的 confidence 头 | **GTX 1660Ti 6GB，8.8 小时** | typed-decisions 77.1%，Brier 0.064 |
| **JevK5** (allebee) | Qwen3.5-4B + LoRA r16（只训 attention） | 4B | 蒸馏：在选项字母 logits 上算 CE；用 Qwen3.6-27B 等教师合成 1.7 万题，外加 26 个公开数据集 train 的 3 万题 | H100 / L40S | JevBench 开源第 1 名，ECE 0.054 |
| OpenJev/SemIf (浏览器版) | Qwen3 / MiniCPM GGUF，直接读选项 token 的 logits | 2–4B | 不训练 | 浏览器 | Qwen3.5-4B 81.3% |

**结论：**
1. 有两条成熟路线：**Encoder 打分路线**（Laya / Verdict）和 **Decoder 读 logits + LoRA 蒸馏路线**（JevK5）。扩散路线（OpenJev）需要 26B 模型，Colab 上训练不了。
2. 小模型完全够用：151M 的 Verdict 在 typed-decisions 上超过了 Jev，而且是在 6GB 显卡上训出来的，非常适合 Colab。
3. 决定效果的关键是**数据格式**和**校准**，不是参数量。Laya 发现，把候选项从 state 挪进 option 列表、把每个选项的信息补全，带来的提升比加数据还大。

## 3. 推荐技术方案（两阶段）

### 阶段 1（主线，免费 T4 可跑）：Encoder 决策模型 “AJev-Base”

**基座选型：**

| 候选 | 参数 | 语言 | 上下文 | 建议 |
|---|---|---|---|---|
| `jhu-clsp/mmBERT-base` | 307M | 1800+ 种，**含中文** | 8k | **✅ 已选定**（需求确认要支持中文；Laya-multilingual 用的也是它） |
| `answerdotai/ModernBERT-base` | 149M | 英文 | 8k | 只做英文、追求最快时选它（Verdict） |
| `answerdotai/ModernBERT-large` | 395M | 英文 | 8k | 英文、追求最好效果时选它（Laya） |

**输入格式（GLiClass / Laya 风格，一次编码同时给所有选项打分）：**
```
[CLS] <type:choice> {instructions} [SEP] [OPT] 选项A: 描述 [OPT] 选项B: 描述 ... [SEP] {state} [SEP]
```
- 取每个 `[OPT]` 位置的隐藏向量，经过 MLP 得到 logit，再在选项之间做 softmax，得到分布。
- `noul` 当成 2 个选项（yes/no，可以附带 criteria.true / criteria.false 的说明）；`score` 当成 K 个有序选项。
- 选项数可变（≤255），不需要为每个任务单独加分类头。

**训练目标（逐步叠加）：**
1. **软标签 KL / CE**：标签是分布，不是 one-hot。来源可以是多个标注者的投票，或者教师 LLM 多次采样的结果。
2. **打乱选项顺序的一致性损失**：同一题把选项打乱两次，两次输出的分布之间算对称 KL。这一步专门解决位置偏置。
3. **RLCD 精调**：给 logits 加噪声后采样 G 个答案，用 proper scoring rule 当奖励（choice 用 log / Brier，score 用 RPS），以组均值作 baseline 做 REINFORCE，同时保留一个软 CE 项，防止训崩。
4. **温度校准**：在验证集上给每种题型（`noul` / `choice` / `score`）各拟合一个温度 T。

**Colab 资源估算：** mmBERT-base 用 bf16/fp16，max_len 1024，batch 8，开梯度检查点，T4 上大约 6–8GB 显存。3–5 万题 × 3 epoch 在 T4 上约 4–6 小时；换 L4 / A100 能快 2–4 倍。

### 阶段 2（可选，Colab Pro L4/A100）：Decoder LoRA “AJev-LM”

- 基座：`Qwen/Qwen3-4B-Instruct-2507`（也可以换成更新的 Qwen3.5-4B，JevK5 用的就是它）；要省显存就用 `Qwen3-1.7B`，免费 T4 用 QLoRA 也能跑。
- 方法：把选项编号成 A/B/C…，prompt 以 `Answer:` 结尾，只取下一个 token 在这些选项字母上的 logits 做 softmax，然后对软标签算 KL。用 LoRA r=16，target 选 q/k/v/o 投影，lr 3e-5，1–2 epoch。
- 优点：理解力更强，能吃长上下文和复杂规则。缺点：慢 5–10 倍，选项多的时候字母 token 不够用，需要分组读取。
- 阶段 2 还有一个用途：拿它当**教师**，为阶段 1 生成更多软标签数据。

### 为什么不直接走扩散路线
DiffusionGemma 26B 光 bf16 权重就超过 50GB，Colab 的 A100 40GB 装不下训练状态，ROI 太低。

## 4. 训练数据集

### 4.1 统一数据格式（JSONL）
```json
{"id": "boolq-123", "source": "boolq", "lang": "en",
 "type": "noul|choice|score",
 "state": "……原文/JSON……",
 "instructions": "Is the passage saying X?",
 "options": [{"name": "yes", "desc": "…"}, {"name": "no", "desc": "…"}],
 "target": [0.92, 0.08]}
```
`target` 一律存成分布：硬标签就转成 one-hot（可以加 0.05 的 label smoothing），多人标注就存投票比例，教师模型就存它的概率。

### 4.2 公开数据集（只用 train split，按题型分组）

| 题型 | 数据集（HF id） | 改造方式 |
|---|---|---|
| noul | `google/boolq`、`nyu-mll/glue`(mnli/qqp/rte)、`facebook/anli`、`fever`、`google-research-datasets/paws` | 问题 / 假设 → instructions，直接是 yes/no |
| noul（审核） | `lmsys/toxic-chat`、`PKU-Alignment/BeaverTails`、`google/civil_comments` | “这段内容是否违规/有毒？” |
| choice（意图/路由） | `PolyAI/banking77`、`clinc_oos`、`AmazonScience/massive`（**含 zh-CN**） | 每题随机采样 5–30 个候选意图，其中包含正确项 |
| choice（主题） | `fancyzhx/ag_news`、`fancyzhx/dbpedia_14`、`dair-ai/emotion`、`cardiffnlp/tweet_eval` | 类别名 + 描述作为 options |
| choice（推理） | `allenai/ai2_arc`、`tau/commonsense_qa`、`Rowan/hellaswag` | 原生多选题 |
| choice（agent） | `osunlp/Mind2Web`、`LocalLLaMA/typed-decisions`(train) | 候选元素 / 动作作为 options |
| score | `Yelp/yelp_review_full`(1–5)、`sentence-transformers/stsb`(0–5)、`nvidia/HelpSteer2`(0–4) | 每一级配上具体描述 |
| 中文 | `clue/clue`（tnews / iflytek / afqmc / cmnli / ocnli）、LCQMC、ChnSentiCorp | 同上，覆盖中文 noul / choice |

建议规模：公开数据共采样 **3–5 万条**，每个数据集最多 3k 条，保证题型均衡（noul : choice : score ≈ 4 : 4 : 2）。

### 4.3 合成数据（决定上限的部分）
所有复刻项目都证明了一点：**教师 LLM 合成的“像真实业务的”决策题**比纯公开数据更有价值。

1. 用强 LLM 生成真实场景，比如工单路由、退款判断、日志告警分级、agent 是否该停。生成内容包括 state + 问题 + 选项 + 判断边界。
2. 对每道题让教师采样 N=5–10 次，或者直接读教师的 logprobs，得到**软标签分布**。
3. 过滤掉教师自己意见不一致（熵很高）的题，或者保留下来专门做校准训练。
4. 反向生成：先选定答案，再让 LLM 构造一个符合它的 state（Laya 的 reverse-generated goals 用的就是这个思路），标签干净。
5. 每道题都做选项打乱、措辞改写的增强。

起步目标：合成 1–2 万题。

## 5. 测试集与评测

| 评测 | 目的 | 对标 |
|---|---|---|
| `LocalLLaMA/typed-decisions` **test**（2,000 决策，4 个业务流） | 主指标，能和现有开源方案直接比 | Jev 0.727 / Laya 0.766 / Verdict 0.771 |
| **JevBench** 公开集（easy / original / hard 共 231 题，`adii-py/jevbench`） | 综合分（智力、校准、速度、成本），需要写一个 adapter | JevK5 62.0 / Jev 63.3 |
| 公开数据集的 **test/validation** split（BoolQ、MNLI、Banking77、MASSIVE zh-CN、CLUE dev…） | 分题型、分语言看能力 | 各自 SOTA |
| 自建 holdout：合成题按**场景**整体留出（不是随机抽样留出） | 检验泛化，防止模型只记住模板 | — |

**指标：**
- Accuracy / 机会校正准确率 `(acc − 1/K) / (1 − 1/K)`
- **ECE、Brier**（校准是 Jev 的核心卖点，必须测）
- **选项打乱一致性**：打乱选项后预测答案改变的比例（OpenJev 18.5% → 2.3%）
- 选择性分类曲线：只回答 confidence 高于阈值的题时，覆盖率和准确率怎么变
- 延迟（T4 上单题 ms，以及批量吞吐）

⚠️ 数据卫生：训练数据和 JevBench / typed-decisions test 之间要做去重（n-gram 或 embedding 相似度），否则跑分会虚高。

## 6. Colab 实操要点
- 免费档：T4 16GB，单次会话最长约 12 小时，随时可能断开 → **每 N 步就把 checkpoint 存到 Google Drive 或 HF Hub**，训练脚本要支持断点续训。
- Pro 档：L4 24GB / A100 40GB，阶段 2 推荐用 A100。
- T4 不支持 bf16，要用 fp16 + GradScaler；L4 和 A100 用 bf16。T4 上 FlashAttention-2 也不可用，ModernBERT 会退回 sdpa。
- 数据预处理（下载和转换公开集、调用教师 API 合成数据）**放在本地或 CPU runtime 上跑**，产出 JSONL 后上传到 HF Datasets 私有仓库，Colab 里直接 `load_dataset`。

## 7. 建议的项目结构与里程碑

```
AJev/
  docs/                       # 本文档
  ajev/
    schema.py                 # 统一数据结构（与 Jev wire API 兼容）
    data/                     # 各公开数据集 → 统一 JSONL 的转换器
    synth/                    # 教师 LLM 合成数据 + 软标签
    model/encoder.py          # mmBERT + option-marker 决策头
    train/sft.py              # 软标签 KL + 打乱一致性
    train/rlcd.py             # RLCD 精调
    calibrate.py              # 按题型拟合温度
    eval/                     # typed-decisions / JevBench adapter / ECE
    server.py                 # FastAPI，兼容 Jev /v1/systemone
  notebooks/
    train_colab_t4.ipynb
```

| 里程碑 | 内容 | 产出 |
|---|---|---|
| M1 | 数据 schema、5–8 个公开数据集的转换器、评测脚本 | 能复现“零样本基线”的分数 |
| M2 | mmBERT 决策头 + 软标签 SFT（Colab T4） | typed-decisions acc ≥ 0.70 |
| M3 | 打乱一致性损失 + 温度校准 + RLCD | ECE < 0.05，打乱后答案改变率 < 5% |
| M4 | 合成业务数据（含中文）+ 再训练 | 对标 Laya / Verdict（≥ 0.76） |
| M5（可选） | Qwen 4B LoRA 版 + 兼容 Jev 的 API 服务 | 两个模型通过 Router 选择 |
