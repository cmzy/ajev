# lora4 训练中被跳过的步：排查记录

> 统计时间：训练进行到第 530 步（共约 1,288 步）。被跳过的步全部题目保存在 `data/lm2/skipped_lora4.jsonl`
> （544 道 = 17 步 × 32 道，每道题的 `meta` 里有所在步、梯度范数、近期中位数、提示词长度和日志里的损失）。
> 生成方法：`scripts/dump_skipped.py`，在本机用与训练相同的分词器（transformers 5.17）重建分批，不触碰训练机。
> 重建结果已校验：日志里每一步记录的“损失最大的 5 道题”都出现在重建出的那一步中。

## 结论

**被跳过的全是“长题集中的步”，不是坏数据。** 跳过规则把材料长的步误判成了尖峰。

| 指标 | 被跳过的 17 步 | 全部 530 步 |
|---|---:|---:|
| 平均提示词长度 | **1,776 token** | 520 token |
| 落在“最长的 20% 的步”里 | **13 / 17** | — |
| 程序生成的难题占比 | **44%** | 12% |
| bev_skills（长政策）占比 | **24%** | 8% |
| 主观评判类占比 | 13% | 8% |
| 简单分类题（other）占比 | **0%** | 37% |
| 每步损失最大的那道题 | 1.8–5.6（中位数约 3） | — |

## 原因

1. **梯度范数随材料长度增长**：每道题虽然只在最后一个位置计算损失，但梯度要传回材料里的每一个 token，
   LoRA 参数的梯度是所有位置的贡献之和。材料越长，梯度范数越大。
2. **步内长度相近**：为了减少补齐浪费，每 512 道题按长度排序后才组成步，所以长题会集中在同一步里。
   一个全是 2,500 token 题的步，梯度范数天然就是短题步的几十倍。
3. **相对阈值的“参照物”是短题**：近期 50 步的中位数主要由短题步决定（约 63% 的步平均不到 400 token），
   长题步的梯度范数轻松超过中位数的 30 倍（这 17 步是 35–93 倍，个别 472 倍）。
4. **不是标签问题**：这些步里损失最大的题只有 1.8–5.6，没有 lora2 时那种 9–15 的“极度自信地答错”。

## 影响

- 被跳过的正好是这一轮新加的长难题。最长的约 106 步里，有 13 步（约 12%）没有被学到。
- 梯度在更新前本来就会被裁剪到范数 1.0，这些步即使不跳过，对模型的改动也有上限，所以跳过保护在这里几乎没有起到保护作用，只是丢掉了数据。

## 下一轮的改法

- **按长度分组比较**：尖峰保护只和**长度相近**的步比较（例如按步的平均长度分成 4 档，每档各自维护中位数），
  或者用“梯度范数 ÷ 步的平均长度”来判断。
- 或者**只拦截 NaN / inf 和极端值**（绝对上限约 2,000），其余交给梯度裁剪。
- 跳过的这 544 道题可以在下一轮里正常训练，不需要剔除。
