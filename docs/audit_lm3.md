## 5. 人工抽查（536 道，67 个数据源，每个数据源 8 道）

结论：**没有发现转换代码映射错标签**；生成题按材料中写明的规则逐题重算（含工作时长、合同日期、汇率），全部正确。
原数据集自带的标注噪声（emotion 按关键词标注、QQP / COLD / BoolQ 个别错标、BANKING77 个别意图有歧义等）无法逐条修正，保留。

已修复的问题：

| 问题 | 影响 | 修复 |
|---|---|---|
| When2Call 官方训练数据的工具“必填参数”全部为空 | 判断“调用 / 追问”的关键信息丢失 | 按参数类型里的 optional 推断必填参数，并保留参数类型和说明 |
| 钓鱼邮件数据实际是“垃圾 / 钓鱼 vs 正常”，问题却只说“钓鱼” | 广告垃圾邮件被当作钓鱼 | 问题改为“垃圾邮件或钓鱼邮件” |
| Feedback-Collection 约 6% 的回答混入评分员评语 | 泄露分数 | 截掉评语，残留的丢弃 |
| HelpSteer3 回答被截到 1,200 字符且只有一个“…” | 3/4 的回答被从中间截断而不自知 | 放宽到 4,000 字符，截断处标明省略了多少字 |
| 客服工单优先级说明“高 = 安全问题”与标签矛盾 | 说明与标准答案冲突 | 说明只描述紧急程度 |
| RAGTruth、MMLU 辅助集按题切分训练 / 评估 | 同一材料同时出现在训练和自建开发集 | 按材料分组切分 |
| 生成题：客服情绪只按抱怨数量计 | 埋在长对话里的温和抱怨被算成“非常愤怒” | 规则写进材料：只看最后 10 条消息，按抱怨数和威胁分级 |
| 生成题：账号锁定归“IT Support（公司内部 IT）” | 与选项说明矛盾 | 归“Customer Service（账户事务）”；新增 bug、报价两类 |
| 生成题：HR 员工重名；申请人的入职天数取值与他人不同 | 答案取决于看哪一行；可靠取值认出申请人 | 姓名不重复，所有员工取值范围相同 |
| 生成题：经理的申请由经理审批 | 自我审批 | 规则改为审批人必须比申请人至少高一级 |
| 生成题：工具题追问句不通顺（"Where is my parcel it right now?"） | 训练不自然的文本 | 每个工具、每个缺失参数单独写自然句子 |
| 生成题：电商条款出现在 HR、分诊规则里；数字不合理 | 不真实 | 干扰条款按领域分开，各自合理取值 |
| 生成题：合同往来记录晚于查询日；节假日落在周末；未写明边界 | 日期不合理、边界有歧义 | 记录限制在查询日之前；节假日只取工作日；规则写明“含第 N 天 / 恰好等于时限算满足 / 期满当天进入新期限” |
| 生成题：成人血压标准用于 1 岁儿童 | 规则不适用 | 分诊题只生成成年患者 |
| 安全日志规则没定义“多次”和各严重程度 | 有歧义 | 写明“至少 5 次失败”和 4 个严重程度的定义 |
